# Kucc-Ycc: WebShop 에이전트의 "막히면 계획을 더 나누기"

LLM 에이전트가 쇼핑 과제(WebShop)를 풀다가 **막히면 계획을 더 잘게 나누는** 전략을 구현하고,
그 효과를 신뢰구간과 함께 측정한 실험 저장소입니다. 계층 계획(AdaPlan-H 계열) 아이디어를
프롬프트 기반 LLM(`claude-haiku-5-5`)으로 옮겨 구현했습니다.

코드와 실험은 모두 [`webshop-adaplan/`](webshop-adaplan/)에 있고, 사용법은 그 폴더의 README를 보세요.

## 한눈에 보는 결과

모든 실험은 WebShop 텍스트 환경(상품 1000개), `claude-haiku-5-5`(effort `low`), 최대 20스텝, 보상 1.0을 성공으로 기준 삼았습니다.

| 실험 | 질문 | 결과 |
|---|---|---|
| 에이전트 수정 전후 (10과제 × 1회) | 막힘 감지·프롬프트 수정이 도움이 되나 | 성공률 20% → 50% |
| **같은 비교를 확대 (20과제 × 3회)** | 위 결과가 믿을 만한가 | **27% → 38%**, 차이 +11.7%p, 95% CI (−5.0, +30.0) → 아직 유의하다고 말할 수 없음 |
| 난이도 표 (100과제 × 3회) | 확장 횟수로 과제 난이도를 매길 수 있나 | 1단계 31개, 5단계 59개로 양극화. 중간 단계는 10개뿐 |
| 전략 탐색 (LLM 교사 vs 무작위 교사) | LLM이 제안한 전략이 더 나은가 | 예산 부족으로 비교 불가. L1_hybrid가 baseline과 성공률은 같고(41.2% vs 41.2%) 토큰은 약 22% 적게 사용 |

### 이 저장소에서 가장 중요하게 본 점

- **첫 실험(20% → 50%)은 과장이었습니다.** 표본을 키우니 27% → 38%로 줄었고 신뢰구간이 0을 포함합니다.
  과제당 1회 결과는 운의 영향이 커서, 이후 모든 비교에 신뢰구간과 짝지은 부트스트랩을 썼습니다.
- **"1레벨로 시작해 막힐 때 확장"은 성공률을 올리지는 못했지만 비용을 줄였습니다.**
  처음부터 3레벨 계획을 만드는 baseline과 성공률이 같고(41.2%), 에피소드당 토큰은 약 22% 적습니다.
- **난이도 척도는 지시문의 겉보기 복잡도로 설명되지 않았습니다.** 속성 수·옵션 수·지시문 길이와의
  스피어만 상관이 0.09~0.17로 약했습니다. 그 난이도가 무엇을 재는지는 아직 모릅니다.
- **실패 원인을 일부 찾아 고쳤습니다.** WebShop 화면은 옵션을 눌러도 바뀌지 않아 에이전트가 선택 여부를
  알 수 없었고, 막힘 감지가 정상적인 옵션 클릭을 막힘으로 셌습니다. 고친 뒤 해당 과제가 2/2 성공했지만,
  이 수정은 위 비교에 포함되지 않았으므로 따로 측정해야 합니다.

## 구성

| 경로 | 내용 |
|---|---|
| `webshop-adaplan/agent.py` | 계층 계획 생성, 막힘 감지, 확장(global / local / hybrid), 에피소드 실행 |
| `webshop-adaplan/difficulty.py` | 확장 횟수 기반 5단계 난이도, 순위 상관 |
| `webshop-adaplan/search.py` | 전략 탐색(파레토 선택, 교사 편집, 예산 상한), 기준 전략과 신뢰구간 비교 |
| `webshop-adaplan/report.py` | 결과(`trials.jsonl`)를 표와 그래프로 정리 |
| `webshop-adaplan/results/agent_fix_haiku/` | 수정 전후 비교(10과제 × 1회)의 원자료, 요약, 그래프 |
| `webshop_results.zip` | 나머지 실험(20과제 × 3회 비교, 난이도 표, 전략 탐색)의 원자료와 각 `RESULTS.md` |
| `strategy_search.py` | 가짜 환경에서 먼저 만든 전략 탐색 파이프라인 (WebShop용은 `search.py`) |

## 실행해 보기

API 키나 WebShop 설치 없이 가짜 환경으로 전체 흐름을 확인할 수 있습니다.

```bash
cd webshop-adaplan
pip install -r requirements.txt
python run.py episode --mock
python run.py difficulty --mock --tasks 1500:1600 --k 3
```

가짜 환경의 숫자는 실제 성능과 무관합니다. 실제 실행 방법(WebShop 설치, Claude API 또는 vLLM)은
[`webshop-adaplan/README.md`](webshop-adaplan/README.md)를 보세요.

## 한계

- 계획 모델이 학습된 AdaPlan-H가 아니라 **프롬프트 기반 LLM**입니다. 원 논문의 결과와 직접 비교할 수 없습니다.
- 표본이 작습니다. 확대판도 20과제 × 3회이고, 전략 탐색은 시드가 1개입니다.
- 전략 탐색은 탐색 예산(400회)이 첫 라운드 도중 소진되어, **교사가 만든 전략이 한 번도 끝까지 평가되지 못했습니다.**
  LLM 교사와 무작위 교사의 비교는 이 설정으로는 결론이 없습니다.
- WebShop은 상품을 사면 끝나므로 잘못 산 경우(보상이 낮은 구매)에는 확장이 일어나지 않습니다.
- WebShop 공식 데이터(Google Drive)가 404여서 Hugging Face 커뮤니티 사본을 썼고(해시는 두 사본에서 일치 확인),
  spaCy 등 일부 패키지 버전을 바꿨습니다. 지시문 처리와 보상 계산이 원본과 조금 다를 수 있습니다.

## 다음에 할 일

1. 난이도 5단계 과제의 실패 원인 분류 (지시문 모순, 검색으로 정답이 안 나옴, 옵션 오선택 등).
   풀 수 없는 과제를 걸러야 난이도 척도가 의미를 가집니다.
2. 옵션 선택 기억 수정의 효과를 같은 조건에서 따로 측정.
3. 시드 3개 이상, 탐색 예산을 늘려 교사 비교를 다시 수행.

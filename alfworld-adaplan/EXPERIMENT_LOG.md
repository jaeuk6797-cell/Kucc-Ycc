# ALFWorld + ADaPT 실험 정리 (EXPERIMENT_LOG)

> 작업이 끝날 때마다 이 파일을 갱신하고 GitHub(`docs/alfworld-environment` 브랜치)에 푸시한다.
> 최신 항목이 맨 위. 숫자는 로그에서 그대로 옮긴 값이며, 해석은 "가설"로 표시한다.

## 0. 설정 한눈에 보기
- 환경: ALFWorld 텍스트 환경, unseen 분할 134개 게임(6개 유형)
- 모델: claude-haiku-5-5 (effort low, 온도 설정 불가), 최대 40스텝
- 전략: `adaplan_M3`(기준, 확장 없음) vs `adaplan_M3_adapt`(막힘 감지 시 해당 단계만 국소 분해, 최대 4회)
- 막힘 감지: 최근 6스텝 중 3번 막힘 (무효 명령 / "Nothing happens." / 같은 (관찰, 행동) 반복)
- M=3, K=1 (온도 0이라 K 롤아웃이 동일해서 K는 측정 불가)
- 예산: 총 $27, 70%($18.90)에서 중단. 에피소드당 약 $0.0057
- 실행: WSL Ubuntu, `./alfenv/bin/python run.py ...` (API 키는 사용자가 터미널에서 직접 export)

- 조치: `--workers N`을 **작업 프로세스**(spawn)로 변경. 프로세스마다 임시 작업 폴더·자기 환경 사용, 누적 비용은 프로세스 간 공유 값으로 예산 보호 유지, 캐시 기록은 메인 프로세스만
- 스레드 실행에서 나온 결과가 섞였을 수 있어 `CODE_VERSION`을 4로 올려 캐시를 새로 시작
- 테스트 8개 통과(프로세스 풀 결과 = 단일 프로세스 결과, 가짜 환경). 실제 ALFWorld에서의 병렬은 재확인 필요
- 참고: 스레드 실행 중 task 10은 두 전략 모두 성공했으나(기준 15스텝, ADaPT 14스텝, 확장 0) 신뢰하지 않음

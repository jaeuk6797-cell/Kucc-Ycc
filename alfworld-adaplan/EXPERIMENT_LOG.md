# ALFWorld + ADaPT 실험 정리 (EXPERIMENT_LOG)

> 작업이 끝날 때마다 이 파일을 갱신하고 GitHub(`docs/alfworld-environment` 브랜치)에 푸시한다.
> 최신 항목이 맨 위. 숫자는 로그에서 그대로 옮긴 값이며, 해석은 "가설"로 표시한다.

## 0. 설정 한눈에 보기
- 환경: ALFWorld 텍스트 환경, unseen 분할 134개 게임(6개 유형)
- 모델: claude-haiku-5-5 (effort low, 온도 설정 불가), 최대 40스텝
- 전략: `adaplan_M3`(기준, 확장 없음) vs `adaplan_M3_adapt`(막힘 감지 시 해당 단계만 국소 분해, 최대 4회)
- 막힘 감지: 최근 6스텝 중 3번 막힘 (무효 명령 / "Nothing happens." / 같은 (관찰, 행동) 반복)
- M=3, K=1 (온도 0이라 K 롤아웃이 동일해서 K는 측정 불가)
- 예산: 총 $27, 70%($18.90)에서 중단. 에피소드당 약 $0.0057
- 실행: WSL Ubuntu, `./alfenv/bin/python run.py ...` (API 키는 사용자가 터미널에서 직접 export)

## 1. 진행 기록 (최신 순)

### 2026-11-19 (3) 프롬프트 개선 + 병렬 실행 구현 (코드 버전 2 → 3)
- **프롬프트** (`agent.py`)
  - 공통(기준·ADaPT 모두): 환경 안내에 "목표에 쓰인 물체 이름 그대로 사용, cup/mug 같은 유사 물체로 대체 금지" 추가
  - ADaPT 분해 전용: 막힘 알림에 "Not yet visited"(가능한 `go to` 중 아직 안 간 곳) 목록 추가, 분해 지시문에 "대상 물체를 못 찾았으면 미방문 장소로 가는 하위 단계를 만들 것" 추가
  - `CODE_VERSION`을 3으로 올려 예전 캐시(`results_cache.jsonl`)는 재사용되지 않음. 이전 20개 에피소드 결과는 구버전 기록으로만 남음
- **병렬 실행** (`run.py --workers N`): 스레드마다 별도 ALFWorld 환경, 비용 계량기는 잠금 + 스레드별 에피소드 비용, API 재시도 6회. 권장 3
- **결과 저장**: `compare`/`pilot` 종료 시 `results/*.md` 자동 저장, `--push`로 커밋·푸시 시도
- `run.py report`: API 호출 없이 캐시에서 현재 버전 결과를 다시 요약(중단·이어하기 실행 포함)
- 테스트 7개 통과(분해 알림의 미방문 목록, 스레드별 비용, 병렬=직렬 결과). 실제 ALFWorld에서의 병렬 동작은 아직 미확인

### 2026-11-19 (2) task 10, 66 궤적 분석 (`show`, 비용 0)
- **task 10 (pick_heat_then_place_in_recep) 4/4 실패**
  - 계획이 목표를 "cup"으로 적었는데 에이전트는 줄곧 **mug 3**을 집어 데우고 cabinet 1에 넣었다(t=6~10). 환경은 이동을 받아줬지만 성공 처리하지 않았다.
  - ALFWorld에서 Cup과 Mug는 서로 다른 물체 유형이라 이것이 원인일 가능성이 높다(가설: 이 게임의 목표 문장을 아직 확인 안 함).
  - 국소 분해(refinement)가 오히려 "mug는 cup 종류"라고 못 박았다. 이후 take → heat → move를 40스텝 끝까지 반복, 확장 4회를 전부 소진.
  - 진짜 cup을 찾으려는 탐색은 없었다(cabinet 1·2, countertop 1만 방문).
- **task 66 (look_at_obj_in_light)**: rep 0 실패(확장 4회), rep 1 성공(확장 2회, 23스텝)
  - 실패 쪽: 계획이 "bowl은 desklamp 아래에 있다"고 가정해 desk 1과 drawer 1~4만 왕복, **desk 2를 끝내 가지 않았다**(bowl은 desk 2에 있음).
  - 성공 쪽: t=17에 desk 2에 가서 bowl을 발견, 집어서 lamp가 있는 desk 1로 이동.
  - 같은 task, 같은 전략인데 "다른 곳도 가본다" 한 번 차이로 갈림. 분해 횟수와 무관.
- **시사점**
  1. 실패 원인은 계획 깊이 부족이 아니라 (a) 목표 물체 유형의 의미적 치환, (b) 미탐색 장소 탐색 실패.
  2. 현재 국소 분해는 막힌 단계의 문장만 다시 쓰고 **새 정보를 주지 않아서** 같은 루프를 되풀이.
  3. 확장 4회 소진 시 실패 0/4, 2회 이하로 끝난 경우 성공 2/2라는 앞선 관찰은 "확장이 많다 = 이미 깊이 막혔다"는 뜻일 뿐, 확장의 효과를 보여주지 못한다.
- **개선 후보 → (3)에서 구현함**
  - 계획/분해 프롬프트에 목표 문장 원문을 넣고 "물체 이름은 목표에 쓰인 그대로, 비슷한 물체로 대체 금지"를 명시
  - 막힘 시 분해 프롬프트에 "아직 가보지 않은 receptacle 목록"을 제공
  - 확인 필요: task 10의 목표 문장(`traj_data.json`의 task_desc)에 cup이 맞는지

### 2026-11-19 (1) 소규모 반복 비교 (5 tasks × 2 reps)
- 대상 task: 10, 66, 98, 107, 130 (에피소드 20개, 누적 $0.1703)
- 기준 5/10, ADaPT 6/10, McNemar p=1.0, 차이 +10%p (95% 구간 -30%~+50%)
- 확장 발동: ADaPT 에피소드 6/10
- 앞선 1회 비교(기준 3/5, ADaPT 2/5)와 결과가 뒤집힘 → **실행 간 흔들림이 전략 간 차이보다 큼**
- 에피소드당 약 1분 → 134×2는 약 4~5시간 (병렬화 필요)

## 2. 방침 (2026-11-19 사용자 결정)
- 목표는 엄밀한 비교 설계가 아니라 **ADaPT 효용의 크기**를 아는 것. 난이도 티어 분석과 반복(reps)은 생략하고, 134개 task × 1회 짝 비교의 성공률 차이(95% 구간)만 본다.
